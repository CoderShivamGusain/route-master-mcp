# CLAUDE.md — mcp-route-master

Context for Claude Code. Carried over from the Claude (Cowork) sessions, Oct–Nov 2026.

## What this is
A free MCP server (Python 3.10+, FastMCP 4.1.4, fully async) that helps people in India find an
intercity bus, check that the operator and links are genuine, and book on the official site
(redBus, MakeMyTrip). The user always pays and enters any OTP themselves. It works with Claude,
ChatGPT and Gemini.
- Live: https://mcp-route-master.onrender.com/mcp (Streamable HTTP, stateless, no auth), health at /health
- Repo: https://github.com/CoderShivamGusain/route-master-mcp (branch main; Render auto-deploys on push)
- Version 0.8.0. Open /mcp: 12 tools, 6 resources, 3 templates, 3 prompts. Signed-in /app/mcp: those plus 7 browser_* tools

## Layout
- `src/mcp_route_master/server.py`: tools, instructions to the AI, command-line entry point. `extras.py`: resources and prompts. `http_options.py`: optional Bearer token and CORS.
- `extension/` (signed-in mode): `app.py` (/app/mcp with Google sign-in, the browser_* tools, the combined ASGI app), `relay.py` (WebSocket hub at /ext/ws), `tokens.py` (Google ID-token check, HMAC extension tokens)
- `route-master-extension/`: Chrome MV3 extension (background.js, page/actions.js is GENERATED by `python -m mcp_route_master.browser.extension_bundle`, page/forms.js, popup/)
- `places/` (resolver, links, dates), `trust/` (operators, safety, bus_types), `booking/` (ranking, seats, guide, checkout), `browser/` (scripts.py: JavaScript run in the tab; pages.py: parsers for captured pages), `common/` (schema, store, textutil), `data/` (hubs.json, operators.json)
- `tests/unit`, `tests/integration`, `tests/browser` (Node and Playwright, skipped without them), `tests/fixtures`
- `docs/` (chatgpt, gemini, remote_http, render), `examples/`, `deploy/`, `render.yaml`, `Dockerfile`, `horizon_app.py`

## Rules (keep these)
- The server never fetches booking sites itself: no scraping and no bypassing bot checks. The AI's browser, or the user, opens the official site.
- Never read, type or automate OTP, card, UPI or password fields, and never pay. The capture script filters these fields out.
- Ask before typing personal data. Show a problem-free summary and wait for the user's "confirm"; if the page changes, show a new summary and wait for a new confirm.
- Where sites ignore scripted clicks: the script marks the element "rm-target" and the AI clicks it with a real click.
- Tool input schemas must stay portable for Gemini: no anyOf, null or $ref (use `common/schema.py`). Every tool is annotated read-only.
- Make minimal changes, keep the tests passing, and add a regression test with every fix.

## Known limitations (from the live tests)
- Only apps with browser control (Claude Desktop with its browser, Claude in Chrome) can book. ChatGPT and Gemini work in paste mode and sometimes ignore the tools.
- redBus government bus groups (UTC, UPSRTC) are collapsed and get missed; results load as you scroll, so the list can be partial.
- The payment page works only in the AI's browser session (redBus "Pay with link" is the workaround). Pre-filled emails and state aren't all flagged.
- The local stdio setup fails in Cowork and Code sessions ("--with ... Distribution not found"); use the hosted URL there.
- Render's free plan sleeps after about 15 minutes idle, so the first call can take about a minute.

## Signed-in mode (built in v0.8.0)
- Turns on when GOOGLE_CLIENT_ID is set (and GOOGLE_CLIENT_SECRET, BASE_URL, JWT_SIGNING_KEY; optional REDIS_URL). Without it, the server runs exactly as before.
- The user is matched by Google `sub`: the connector's OAuth sign-in (FastMCP GoogleProvider) and the extension's token (from /ext/token) carry the same one. The newest extension connection per user wins.
- Safety gates: browser_action "continue" fails closed. It works freely only on the seats and points pages. On the passenger page it needs requested_seats, a clean summary and user_confirmed=true. Any other page is refused.
- The extension: only redbus.in and makemytrip.com; trusted clicks via chrome.debugger; refuses secret fields and payment pages; runs commands one at a time.
- Extension ID hajmndkodaikljkjjbnmpbiagfacmmei (fixed by `key` in manifest.json). Google redirect URIs: BASE_URL/auth/callback and https://hajmndkodaikljkjjbnmpbiagfacmmei.chromiumapp.org/

## Decisions and next steps under discussion
1. Guided mode for phones: accept buses and seats read from screenshots, deep links with filters, redBus affiliate links (EarnKaro/Awin).
2. Plan A, a route-master Chrome extension (built in v0.8.0; still needs a live test with real Google sign-in):
   - the extension connects out to the server over a WebSocket relay;
   - Google OAuth sign-in on both the connector and the extension, matched by account;
   - Chrome's "background" permission so it starts with the computer; work done in a minimised window;
   - limited to redbus.in and makemytrip.com; free to build: Load unpacked, Google OAuth in Testing mode (up to 100 users).
3. Long term: an official B2B bus API (redBus SeatSeller, AbhiBus, Travelyaari…) plus UPI payment links, which works on every device.
